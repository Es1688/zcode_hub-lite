# PORT.md — Порт guided-research на ZCode (плагин)

> **Lite-копия.** Это копия порта 0.1.0 для лайт-дистрибутива Engineering Hub
> (репозиторий zcode-hub-lite). Upstream-снапшот `guided-research-main/` и ADR
> о порте (ADR-0003) живут в основном хабе на машине-источнике
> (`~/work/it/zcode/`) — в этом репозитории их нет и они не требуются для работы
> плагина. Ниже пути установки даны относительно клона этого репозитория.

Перенос скилла `guided-research` (upstream `github.com/abbnv/guided-research`, MIT,
автор abbnv) с Claude Code / Kimi Code CLI на ZCode. Источник-эталон —
upstream-снапшот в основном хабе. Upstream на момент порта (18.10.2026) — один
коммит, снапшот от 10.09.2026 актуален. Решение о внедрении — ADR-0003 основного
хаба.

**Форма доставки — локальный плагин** `guided-research` маркетплейса `dev-it-zcode`
(прецедент: adversarial-review, ADR-001). Решение пользователя от 18.10.2026:
плагин; тело скилла — английское; объём — хирургический порт + улучшения.

## Раскладка

```
<клон zcode-hub-lite>/plugins/
├── marketplace.json                # каталог локального маркетплейса dev-it-zcode
└── guided-research/                # копия плагина (dir name == name в манифесте)
    ├── .zcode-plugin/plugin.json   # name, version, description, skills, commands
    ├── skills/guided-research/
    │   ├── SKILL.md                # оркестратор (EN, хирургический порт)
    │   └── references/report-template.md  # скелет отчёта и блоки-паттерны (улучшение)
    ├── commands/guided-research.md # тонкая обёртка с $ARGUMENTS
    └── PORT.md                     # этот файл
```

Компоненты `agents` и `hooks` отсутствуют: скилл односубъектный (главный агент
ведёт диалог и исследует сам), внешних зависимостей нет.

## Маппинг механизмов

| Механизм upstream (Kimi/Claude) | Этот порт (ZCode) |
|---|---|
| `ask_user` (кнопки-варианты, произвольный ввод) | `AskUserQuestion` (≤4 вопросов и 2–4 варианта за вызов; произвольный ввод — через встроенный «Other») |
| Шаг 1: 2–3 варианта цели одним ask_user | Один вопрос `AskUserQuestion` с 2–3 вариантами — без изменений |
| Шаг 2: 4–6 вопросов «одним вызовом ask_user, максимум два захода» | `AskUserQuestion` держит ≤4 вопросов → 4–6 вопросов разбиваются на ≤2 вызова; лимит «максимум два захода» сохранён дословно |
| Шаги 3–5 «одним экраном» | Один вызов `AskUserQuestion` из 3 вопросов (формат ок? / стиль / источники) |
| Неявный веб-поиск хоста | Явно `WebSearch` + `WebFetch`; ограничение WebSearch (US-only) задокументировано в шаге 6 с компенсацией: уточнённые запросы + `WebFetch` прямых URL форумов/отзовиков/сайтов игроков |
| Тело скилла RU | Тело EN (решение пользователя); диалог и отчёт — на языке пользователя (явное правило в шапке скилла) |
| `description` RU ~660 симв. | EN-база + русские триггер-фразы (иначе авто-триггер на русских запросах не сработает); длина проверена ≤1024 симв. |
| Чек-лист шага 7 в теле скилла | Сохранён в теле (hard-wired) + расширенный шаблон отчёта вынесен в `references/report-template.md` (улучшение; при нерезолве reference скилл восстанавливает скелет из шага 3) |

Итого прерываний пользователя: 3–4 вызова `AskUserQuestion` за прогон — как в
upstream (лимит «3–4 прерывания» сохранён).

## Что перенесено 1:1

Семь шагов алгоритма, формула цели, правила генерации вопросов, демо-фрагмент до
старта исследования, варианты стиля и источников, жёсткие правила исследования
(цитаты дословно, ничего не выдумывать), чек-лист качества перед сохранением,
секция «Жёстко зашито», результат всегда `.md` в `reports/` текущего проекта.

## Установка (UI, один раз)

1. **Plugin Marketplace → Discover → `+`** → добавить локальный маркетплейс:
   путь `<клон zcode-hub-lite>/plugins` (инструкция — в README репозитория).
2. **Personal → dev-it-zcode → Guided Research** → **Install**.
3. Новая сессия — скилл и команда `/guided-research` подхватятся автоматически.

## Обновление после правок исходника

1. Поднять `version` в `.zcode-plugin/plugin.json` и синхронно в `marketplace.json`.
2. UI: Marketplace Sources → **Refresh** у `dev-it-zcode`.
3. UI: Personal → guided-research → **Update** → проверить версию.
4. Новая сессия для проверки.

## Обновление upstream

Снапшот upstream — отдельный репозиторий с единственным коммитом импорта в
основном хабе (машина-источник). При появлении upstream-обновлений: обновить
эталон отдельной задачей в основном хабе, провести diff по алгоритму, отразить
изменения в порте, поднять версию плагина и скопировать в этот репозиторий.

## Известные отличия и ограничения

- **WebSearch US-only** — выдача по неанглоязычным рынкам может смещаться;
  компенсация в шаге 6 (уточнённые запросы + `WebFetch` прямых URL). Для нишевых
  русскоязычных площадок (отзовики, форумы) часть источников придётся доставлять
  прямым `WebFetch`.
- **Произвольный ввод только через «Other»** в `AskUserQuestion` — пользователь
  может править любую предложенную формулировку там; скилл обязан учитывать такой
  ответ как валидный выбор, а не как отказ.
- **Нет межшаговой памяти диалога сверх сессии** — как в upstream; при вылете
  сессии вводные собираются заново.
- `references/report-template.md` резолвится от базы скилла в листинге плагина;
  при недоступности скилл работает автономно (скелет из шага 3 + чек-лист из тела).
