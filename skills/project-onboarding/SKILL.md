# project-onboarding — карта незнакомого проекта

Цель — за один проход понять проект и зафиксировать это в `PROJECT_MAP.md` в корне
репозитория. Пользователь учится разработке: карту пиши понятно, термины поясняй.

## INPUT

Путь к репозиторию (по умолчанию — текущая директория).

## PRECONDITIONS

- Сначала прочитай `AGENTS.md` и `.zcode/project.yaml`, если они есть: часть ответов
  уже записана — не дублируй работу, сверяйся с ними.
- Работай только чтением до момента записи PROJECT_MAP.md.

## STEPS

1. **Стек**: найди манифесты (`package.json`, `pyproject.toml`/`requirements*.txt`,
   `appsscript.json`, `Dockerfile`, `*.ipynb` …). Язык, версия, сборщик, рантайм.
2. **Структура**: дерево каталогов на 2–3 уровня; назначение каждого верхнего каталога.
3. **Git**: ветка, последний коммит (`git log -1`), незакоммиченные изменения, remote,
   теги.
4. **Тесты**: где лежат, как запускаются (скрипты package.json, pytest, README проекта).
5. **Entry point**: главный файл или команда запуска.
6. **Зависимости**: прямые — из манифеста. Устаревание НЕ проверяй (отдельная задача).
7. **Документация**: README, docs/, инструкции.
8. **Данные**: каталоги данных; пометь «только чтение», если так по AGENTS.md.
9. **Состояние**: что в работе (WIP), что выглядит завершённым/заброшенным.
10. Запиши `PROJECT_MAP.md` по формату OUTPUT.

## VALIDATION

Каждый факт в карте подтверждён файлом или git-командой; ничего не домысливай.
Неизвестное помечай `—` с пометкой «не установлено», а не пустым местом.

## OUTPUT — формат PROJECT_MAP.md

```
# PROJECT_MAP — <имя проекта>

Language: <язык версия>   Build: <инструмент>   Tests: <как запускать>
Entry point: <путь или команда>
Git: ветка <b> • последний коммит <sha, дата> • remote <url или «нет»>
Data: <каталоги данных и политика>
Docs: <README / docs / инструкции>

Architecture:
    <путь> — <назначение, одна строка на элемент>

State: <1–3 предложения о текущем состоянии проекта>
```

## POSTCONDITIONS

- `PROJECT_MAP.md` записан в корень репозитория.
- Предложи закоммитить его стандартным циклом (`git-start-task` → `docs: add
  PROJECT_MAP` → `git-finish-task`); merge — только с разрешения пользователя.
- Если обнаружены проблемы (нет манифеста, секреты в git) — доложи отдельно, не молчи.
