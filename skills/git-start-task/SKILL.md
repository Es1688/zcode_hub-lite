# git-start-task — стандартное начало задачи (lite)

Пара к `git-finish-task`. Жизненный цикл: start → работа → finish. Пользователь только
учится git — **каждую команду сопровождай одной строкой «что она делает и зачем»**,
простым языком, без жаргона.

## PRECONDITIONS

1. Это git-репозиторий и есть `.zcode/project.yaml` (нет — сначала предложи онбординг
   проекта скиллом `project-onboarding`, не начинай задачу вслепую).
2. Ты на `main` и рабочий статус чист (`git status`). Если есть незакоммиченные
   изменения — остановись и покажи их пользователю, вместе решите: закоммитить,
   отложить (`git stash`) или удалить.
3. Формулировка задачи от пользователя понятна.

## STEPS

1. Идентификатор задачи: `<ГГГГММДД>-<slug>` (дата сегодня, slug — короткое имя
   по-английски через дефисы, например `20261109-lite-hub`).
2. Ветка: `feature/<slug>` от `main`.
   Поясни: «ветка — это черновик: все изменения задачи живут в ней, main остаётся
   рабочим; в конце ветка вольётся обратно через merge».
3. Файл `.zcode/tasks/<id>.md` по шаблону
   `<ZCODE_DIR>/templates/task-context.template.md`. Заполни: Задача, Требования,
   Ограничения (из AGENTS.md проекта), Acceptance criteria (чекбоксы), Изменяемые
   файлы, Статус: in-progress.
4. Одним сообщением покажи пользователю рамку задачи (ветка + acceptance criteria)
   и убедись, что он согласен, затем приступай к работе.

## VALIDATION

- Ветка создана от `main`; файл задачи существует и заполнен (без пустых разделов).
- Задача НЕ начинается, пока рамка не согласована.

## OUTPUT

Имя ветки, путь к файлу задачи, рамка задачи одной строкой.

## POSTCONDITIONS

- По завершении работа закрывается через `git-finish-task`.
- Если задачу передумали — удали ветку и файл задачи, доложи.
